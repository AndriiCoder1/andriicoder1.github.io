EverRest — Digital Memorial Platform SaaS

📺 Watch the Demo

EverRest is an ethical, secure, and scalable SaaS solution for creating memorial pages, built with privacy-first architecture and tailored for the Swiss market. The platform provides partners (funeral homes) with tools to manage memorials, while families get private access to edit content and moderate tributes.

Public Access & QR Codes

Each memorial receives a unique QR code that can be placed on a tombstone or monument. Friends and relatives can:

  • Scan the QR code to visit the public memorial page
  • Leave a tribute (condolence) without registration
  • Browse memories and photos

The public page is available via a short link (e.g., ....../memorials/ANNMUL2025/public/), which can be shared on messengers or social media.

Frontend & UI/UX Design

The public-facing memorial pages are designed with emotional sensitivity and accessibility in mind, using pure HTML/CSS/JavaScript with Django templates.

  • Glassmorphism Design: Semi-transparent cards with backdrop-filter: blur() create a floating, ethereal effect
  • Smooth Animations: CSS transitions and keyframe animations for logo appearance and card reveals
  • Responsive Layout: Fully adaptive grid and flex layouts for all device sizes (mobile, tablet, desktop)
  • Accessible Forms: Clean, minimal tribute form with focus states and clear error handling
  • Emotional Visuals: Mountain background with parallax scrolling, animated logo (ER + EverRest), and soft color palette (blue accents)
  • No External Frameworks: Pure HTML/CSS/JavaScript — fast load times and no dependency overhead

AI Tribute Moderation (Local, Offline)

The built-in Ollama (phi3:latest) model runs entirely locally — no data leaves the server.

  • Tribute analysis completes in under 20 seconds (tested on 8GB RAM running the full stack: Django, Celery, and Ollama simultaneously)
  • Family tributes bypass AI moderation: Tributes submitted by family members (via token-protected family dashboard) are published instantly without AI checks — the system trusts family content
  • Guest tributes are AI-moderated: All tributes from guests go through the full AI moderation pipeline before publication
  • Moderation criteria (for guests):
    • matching the deceased's last name in the tribute text
    • author name verification (guest leaves their name)
    • text sentiment analysis (detects respectful vs inappropriate content)
    • confidence thresholds (80% auto-approve, 70% auto-reject, 40–70% flagged for family review)
  • Respectful anonymous-style tributes: The AI passes tributes that are respectful even if they don't mention the deceased's name
  • Flagged tributes: When the AI is uncertain (40–70% confidence), the tribute is marked for family review — family can approve or reject it via the family dashboard
  • Guest permissions: Guests can submit tributes but cannot edit or delete them once submitted
  • Family moderation: Family members can approve, reject, or delete flagged tributes through the token-protected family dashboard
  • Manual override: If a guest tribute needs removal (e.g., inappropriate or unwanted), the family can contact the platform admin, who can delete it via the admin panel (all actions logged)
  • Family's own tributes: Family members can edit or delete tributes they personally wrote using the family dashboard
  • Data protection & audit logging: All actions are logged (AuditLog) with IP, timestamp, and user details — cross-user edits are not allowed

  • Multi-language support: DE, FR, IT, EN for tributes and UI

    Performance & Scalability

  • Load Testing: Conducted stress testing using custom Python multi-threading scripts against a Waitress WSGI server (4 threads).

    • Test Volume: 100 mixed requests (public pages, family pages, family tributes, and AI-moderated guest tributes).
    • Success Rate: 96–100% across multiple test runs.
      • Run 1 (10s timeout): 96% success. 4 requests failed due to local AI inference (Ollama) exceeding the 10-second limit under heavy concurrent load.
      • Run 2 (30s timeout): 100% success. This confirmed that the system handles the load, but the AI step requires asynchronous processing.
    • Average Response Times (under concurrent load):
      • Public Memorial Page (GET): ~0.22s
      • Family Dashboard (GET, token auth): ~0.87s
      • Family Tribute (POST, bypasses AI): ~1.00s
      • Guest Tribute (POST, full AI moderation): ~5.46s
    • Architectural Solution: The local Ollama model (phi3) runs on CPU, which accounts for the latency (~5s). In production, this is offloaded to Celery background workers, keeping the API response time for guests under 1 second while AI processes the text asynchronously.

  • Architecture Ready for Scaling:

    • Database: PostgreSQL (indexes, query optimization).
    • Background tasks: Celery + Redis (moves heavy AI tasks out of the synchronous HTTP cycle).
    • Static & media: Nginx + AWS S3 (or local storage).
    • Target Audience: Built to handle the Swiss market. Horizontal scaling (adding more Gunicorn workers, separating AI workers) can support high traffic.

    Security & Privacy

  • Role-based access:

    • Partners (funeral homes): Admin panel access, memorial creation
    • Families: Unique tokens, content editing, media uploads, tribute management
    • Guests: View only, tribute submission (AI-moderated)
  • Audit logging: All critical actions are logged (IP, timestamp, user). Cross-user edits are not allowed.
  • Privacy-first architecture (GDPR/FADP principles): Data retention policy, right to request/delete personal data, consent handling.
  • Local AI: Ollama runs locally within the Docker network. No data is sent to third-party AI APIs.

Deployment

# Clone the repository
              git clone https://github.com/AndriiCoder1/copy_everest.git
              cd copy_everest
              
              # Configure .env (copy .env.example and fill in)
              cp .env.example .env
              
              # Start all services
              docker-compose up -d
              
              # Apply migrations
              docker exec -it copy_everest-web-1 python manage.py migrate
              
              # Create superuser
              docker exec -it copy_everest-web-1 python manage.py createsuperuser
              
              # Load sample data (optional)
              docker exec -it copy_everest-web-1 python manage.py loaddata datadump.json
